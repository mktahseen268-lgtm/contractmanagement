# 03 — Design System

> Direction **B — "Trust Workspace", skinned to the shared dashboard reference** (locked 2026-05-12 — see Doc 02). The system below is **production-safe, WCAG-AA, light+dark, LTR+RTL** today. Tokens are CSS custom properties + a Tailwind theme extension; components are shadcn/ui-based wrapped in `@cm/ui`.

---

## 0. Branding note (current — provisional)

The visual branding **mirrors the attached reference**: friendly, light, airy; a **friendly azure-blue accent**; **generously rounded** white cards (~16px) with **soft, visible shadows**; a very-light cool-gray canvas; **colorful pastel category tiles** (the reference's "Quick Access" pattern); a solid-blue primary action; the live progress tray; the grouped activity rail; the upgrade card. Density is **low-to-comfortable** by default (the `compact` toggle still ships).

**This is a skin, not a structural change** — it's all in this doc's tokens. The brand identity is captured in **one accent token + a small brand-token set**:
```
--color-accent             #3E7BFA   /* friendly azure blue — the one knob */
--color-accent-hover       #2F66E0
--color-accent-active      #2657C9
--color-accent-fg          #FFFFFF   /* text/icons on the accent fill */
--color-accent-subtle-bg   #EAF1FE   /* light-state of selected/active surfaces */
--color-accent-ring        #3E7BFA   /* focus ring */
--brand-logo               <asset>   /* the wordmark/mark */
--brand-radius-scale       1.0        /* multiplier if a brand wants tighter/looser corners */
```
When the client supplies final branding (logo, colors, name), **only this section + §2 change** — every component reads `--color-accent*`, so a re-skin is a token swap, not a refactor. Tenants also get per-workspace white-label overrides of these (Doc 08, Module 22).

The **intelligence accent (§2.2) is deliberately NOT the brand color** — it's a violet/cyan family chosen to stay distinct from the azure brand blue, so AI/OCR surfaces are always recognizable; it stays constant even when the brand color changes (or co-brands, tenant's choice).

## 1. Token architecture

Three tiers — **primitives** (raw scales) → **semantic** (role-based, theme-aware) → **component** (per-component overrides). UI code only ever references **semantic** tokens. Themes (`light`, `dark`) and direction (`ltr`, `rtl`) swap at the `:root` / `[data-theme]` / `[dir]` level.

```
primitives:   --indigo-600: #4F46E5;  --slate-50: #F8FAFC;  --space-4: 16px; ...
semantic:     --color-bg-canvas: var(--slate-50);  --color-accent: var(--indigo-600); ...
component:    --btn-primary-bg: var(--color-accent);  --card-radius: var(--radius-lg); ...
```

### 2.7 Confidence scale (AI/OCR — uses the intelligence accent family)

| Band | Visual | Behavior |
|---|---|---|
| ≥ 90% `high` | teal chip `●92%`, solid | auto-accepted; shown for transparency |
| 60–89% `medium` | amber chip `●74%` | flagged "review"; included in "Verify all" sweep |
| < 60% `low` | red chip `●41%` | "needs you"; field empty or highlighted; cannot auto-fill key metadata |

## 4. Spacing, radii, elevation, layout

- **Spacing scale** (4px base): `0,2,4,6,8,12,16,20,24,32,40,48,64,80,96`. Tokens `--space-1`…`--space-24`. The reference is **airy** — default card padding 20–24, section gaps 24–32, generous gutters; the `compact` density mode tightens these ~25% for power users.
- **Radii** (rounder than the original baseline, matching the reference; scaled by `--brand-radius-scale`): `radius-sm` 8 (inputs, small chips) · `radius-md` 10 (buttons, default controls) · `radius-lg` 14 (panels, sheets, modals, dropdowns) · `radius-xl` 16 (cards — the workhorse) · `radius-2xl` 20 (large feature cards, the Quick-Create tiles, the upgrade card) · `radius-full` 999 (pills, avatars, the search field).
- **Elevation** (soft + slightly more present than "Stripe-restrained" — the reference's cards visibly float):
  - `e0` flush — `box-shadow: none; border: 1px solid border-subtle`
  - `e1` raised card (the default for cards/tiles) — `0 1px 2px rgba(20,33,61,.04), 0 4px 12px rgba(20,33,61,.06)`
  - `e2` dropdown/popover — `0 4px 16px rgba(20,33,61,.10), 0 2px 6px rgba(20,33,61,.06)`
  - `e3` modal/sheet — `0 18px 48px rgba(20,33,61,.18)`
  - `e-hover` — cards lift gently on hover: transition `e1 → 0 2px 4px rgba(20,33,61,.05), 0 8px 24px rgba(20,33,61,.10)` (140ms)
  - `e-ai` — the `ai-glow` token (only on "thinking" elements)
  - Dark mode: shadows are subtler; rely more on `bg-surface` lightness steps + borders.
- **Category tiles** (the reference's "Quick Access" pattern → our **Quick Create** tiles, file-type/folder glyphs, and any "pick a thing" grid): a `radius-2xl` square (or short rectangle), a pastel-tinted background derived from one of 6 brand-adjacent hues, a colorful 24px glyph centered on it, a label below; the 6 tile hues — `tile-blue #5B8DEF / bg #EAF1FE`, `tile-violet #8B7BF5 / bg #F1EEFD`, `tile-cyan #2BC0D4 / bg #E6F8FB`, `tile-amber #F6B83C / bg #FEF5E4`, `tile-coral #F5736B / bg #FDECEB`, `tile-green #3FBF7F / bg #E8F7EF` — all WCAG-checked for the glyph-on-tint contrast, all available in dark-mode variants. Tiles get the `e1` → `e-hover` lift.
- **Layout grid:** 12-col fluid, `max-w` 1440 for centered marketing/auth; the app shell is full-width. Content gutters 24/32. Breakpoints: `sm` 640 · `md` 768 · `lg` 1024 · `xl` 1280 · `2xl` 1536.
- **Shell metrics:** icon rail 56px (collapsed) / 240px (expanded with labels) · contextual sidebar 260px (collapsible) · right drawer 360px (collapsible, resizable 320–520) · top bar 56px · content min 720px before sidebar auto-collapses.
- **Z-index scale:** base 0 · sticky headers 10 · dropdowns/popovers 1000 · drawers 1100 · modals 1200 · toasts 1300 · command palette 1400 · tooltips 1500.

## 5. Motion

| Token | Duration / easing | Use |
|---|---|---|
| `motion-fast` | 120ms ease-out | hovers, color/opacity, small toggles |
| `motion-base` | 180ms ease-out | most enter/leave, accordions, tabs |
| `motion-emphasis` | 240ms cubic-bezier(.2,.8,.2,1) | sheets, modals, page section reveals |
| `motion-spring` | spring(stiffness 300, damping 30) | drag (signature fields, workflow nodes), reorder |
| `motion-aurora` | 6s ease-in-out infinite alternate | the "thinking/scanning" breathing glow on AI surfaces only |

Rules: skeletons (shimmer) over spinners for content; spinners only for in-button or <1s waits; toasts slide+fade from bottom-right (or bottom-left in RTL); the Progress Tray docks/undocks with `motion-emphasis`; **all of the above collapse to instant / static under `prefers-reduced-motion`** (aurora → static `ai-aurora` gradient at low α; sweeps → none).

## 6. Iconography

`lucide-react` (clean, consistent, RTL-friendly, huge set) as the base set; 1.5px stroke at 20px and 24px. Custom marks for: the brand logo, the **Verified seal** (shield + check, embossed style), the **AI spark** (the assistant mark), file-type glyphs (PDF/DOCX/scan), and signature/initials/stamp field markers. Icon-only buttons always have `aria-label` + tooltip. Directional icons (chevrons, arrows, back/forward, send, indent) **mirror in RTL**; non-directional ones (search, settings, bell, check, the brand mark) do **not**.

## 7. Component library (`@cm/ui` on shadcn/ui)

### 7.1 Primitives (theme/RTL-aware wrappers of shadcn)
Button (variants: `primary`, `secondary`, `ghost`, `outline`, `destructive`, `link`; sizes `sm/md/lg`; `loading`, `iconOnly`), IconButton, Input/Textarea/NumberInput, Select/Combobox/MultiSelect, Checkbox/Radio/Switch, DatePicker/DateRangePicker, Slider, Tabs, Accordion, Tooltip, Popover, DropdownMenu, ContextMenu, Dialog/Modal, Sheet (side: `start`/`end`/`bottom` — logical), Drawer, Toast/Toaster, Alert/Banner, Badge, Tag/Chip, Avatar/AvatarStack, Progress (linear + radial), Skeleton, Separator, Breadcrumbs, Pagination, Tooltip, ScrollArea, Resizable panes, Command (⌘K), Calendar, Kbd.

### 7.2 Patterns
- **DataTable** — virtualized, sortable, resizable/reorderable/hideable columns, sticky header + sticky first column, inline edit cells, row selection + bulk bar, density toggle, saved-view aware, empty/loading/error states, server pagination, CSV export. The single most-used surface in the app.
- **FilterBar** — chip-style filters (stage, owner, type, tag, date range, risk, custom fields), saved views, "clear all", result count, share-view.
- **PageHeader** — title + status + breadcrumbs + primary/secondary actions (always top-end), optional tabs row beneath.
- **SideSheet form** — for quick edits (metadata, add signer, comment) without leaving context; sticky footer (Cancel / Save).
- **EmptyState** — illustration + headline + one-line value prop + primary action + "learn more"; one per list/section. (We do this; the Dropbox ref doesn't.)
- **StatCard / KpiCard** — label, big tabular value, delta vs prior period (▲▼ with color), optional sparkline or radial, optional click-through. Some variants carry a single donut (Dropbox-ref echo).
- **ActivityFeed / Timeline** — grouped by day/"x ago", avatar + actor + action + object + timestamp; expandable detail; filterable; used for contract activity, audit (read-only variant with hash chip), notifications.
- **ProgressTray** — dockable bottom-end panel; tracks Celery jobs (OCR batch, bulk import, PDF gen, mass-send); per-item rows with status (queued/running/done/failed) + retry + cancel + "open result"; minimizable to a pill; persists across navigation; ARIA live region. **Reused everywhere async happens.**
- **CommandPalette (⌘K)** — fuzzy search contracts/templates/people/settings + run actions ("Create contract", "Switch workspace", "Toggle theme", "Switch to Arabic", "Go to audit log") + recent items.

### 7.3 CLM-specific compound components
- **LifecycleBar** — the 10-state spine rendered as a dot-track (compact, for list rows) or a labeled segmented bar (full, for contract header), current step highlighted, hover shows who/when, click jumps to that section/tab.
- **StatusPill** — lifecycle/risk/confidence pills, icon + label, muted bg, sizes; never color-only.
- **ConfidenceChip** — `●NN%` with band color + tooltip ("Extracted from page 3, line 14 — click to view source"); clicking pulses the source highlight in the DocViewer.
- **SignerRow** — order badge, avatar/name/email, role (signer/approver/CC), method (e-sign/in-person), status (waiting/viewed/signed/declined) with timestamp, "remind"/"reassign"/"edit" actions.
- **RiskBadge** + **RiskPanel** — severity badge; panel lists flagged clauses with severity, rationale, suggested fix, "accept risk"/"request change"/"insert suggested clause".
- **AuditEntry** — actor, action, target, timestamp, IP/device/location, before→after diff (where relevant), the entry's hash chip + "verify chain" affordance; immutable styling (locked icon).
- **DocViewer** — renders PDF (pdf.js) or the contract block document; an **overlay layer** for: OCR bounding boxes, signature/initial/date fields (placement & signing), comments/pins, AI highlights, redline markers; zoom/fit/page-nav/thumbnails/search-in-doc; print/download (with watermark for drafts).
- **BlockEditor** — the Notion/PandaDoc editor (full spec Doc 11): blocks, slash menu, variables, clause inserts, comments, suggestions, AI commands, version history.
- **WorkflowCanvas** — the visual automation builder (full spec Doc 10): node palette, draggable nodes, edges, condition nodes, parallel/sequential branches, escalation, validation, "simulate".
- **VerifiedSeal** — the trust mark; popover shows hash, signing cert, timestamp authority, "unaltered since {date}", "view certificate of completion (PDF)".
- **IntegrityBanner** — the red header state when a stored file's hash mismatches; "this document may have been altered — view audit / contact admin".
- **KpiDonut / TrendChart / FunnelChart / Heatmap** — chart wrappers (recharts or visx) with our viz palette, tooltips, empty/loading states, RTL-aware axes.

### 7.4 States every component must define
`default · hover · focus-visible (2px accent ring, 2px offset) · active/pressed · disabled · loading · error · readonly/locked · selected · empty (lists) · skeleton`. Plus light & dark, plus LTR & RTL. Storybook story per state.

## 8. Dark mode

A true peer, not an inversion. Strategy: define every semantic token for both themes; toggle via `data-theme="dark"` on `<html>` (respecting `prefers-color-scheme`, with a user override persisted per device + per account). Dark canvas `#0C0F14` (deep slate, not pure black — pure black causes halation on OLED with our type), surfaces step up in lightness, borders carry more weight than shadows, the aurora/AI glow is slightly brighter, status colors are lightened for AA on dark. Charts get a dark-tuned palette. The contract "paper" stays near-white even in dark mode (a document is a document) with an option for a sepia/dark reading mode in the viewer settings.

## 9. RTL / bilingual tokens (see Doc 13 for the full strategy)

- `dir="rtl"` on `<html>` when `lang=ar`; **all CSS uses logical properties** (`margin-inline-start`, `inset-inline-end`, `padding-block`, `border-start-start-radius`, `text-align: start`). No `left`/`right` in app CSS.
- Layout mirrors: icon rail and sidebar move to the right, drawer to the left, breadcrumbs and steppers reverse, table column order reverses (but numeric columns keep LTR number rendering), toasts to bottom-left.
- Icons: directional ones mirror (`scaleX(-1)` via a `data-flip` utility), brand/document/non-directional ones don't.
- Type: `font-arabic` swaps in; larger line-height (Arabic ascenders/descenders), slightly larger base size (15px) for legibility; never italicize Arabic; never letter-space Arabic.
- Mixed content: numbers, code, emails, URLs, English brand names render LTR inside RTL text via `bdi`/`unicode-bidi: isolate`.
- Date/number/currency formatting via `Intl` with the active locale; calendars support Gregorian + Hijri (display toggle).

## 10. Tailwind / implementation notes

- Tailwind config extends `colors`, `fontFamily`, `borderRadius`, `boxShadow`, `spacing`, `screens` from the semantic tokens (which are CSS vars → themes swap with zero JS reflow cost).
- Use `tailwindcss-logical` (or `dir`-variant utilities) so `ms-4`, `pe-2`, `start-0`, `text-start` etc. are first-class — discourage `ml/mr/left/right` via lint rule.
- `tailwind-merge` + `cva` (class-variance-authority) for component variants (the shadcn pattern).
- A `prefers-reduced-motion` Tailwind variant gates all `motion-*` utilities.
- Ship a Storybook with: token reference, every component × every state × light/dark × LTR/RTL, copy/voice guidelines, and accessibility notes per component. This *is* the design handoff.
- **Voice & tone:** plain, confident, specific. "3 approvals waiting on you" not "You have pending items". Errors say what happened + what to do. No exclamation marks in system copy except success confirmations. Legal-adjacent copy reviewed by counsel. Bilingual copy is *translated and reviewed*, never machine-only.

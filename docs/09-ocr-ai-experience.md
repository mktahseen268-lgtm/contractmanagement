# 09 — OCR & AI Experience (the differentiator)

This is the layer the brief calls "one of the MOST IMPORTANT parts." It must feel **futuristic, enterprise-grade, intelligent, polished, easy** — and, the part the brief implies but doesn't say: **honest** (a contract system that hides its uncertainty isn't trustworthy). The whole experience lives on the **"intelligence" surface** (aurora tint + subtle glow + confidence chips — Doc 03 §2.2) so users always know when a machine is talking.

---

## 1. Design principles for the intelligence layer

1. **Show the work.** Every machine output is source-linked: click it → the exact region in the document highlights and pulses. Nothing is asserted without "here's where I got it."
2. **Calibrate trust.** Every output carries a confidence band (Doc 03 §2.7). ≥90% = auto-accepted (still visible). 60–89% = "review" (in the verify sweep). <60% / not-found = "needs you" (empty or flagged). Confidence is never hidden behind a happy "✓ done."
3. **Human always wins.** Any extracted/generated value is editable; overrides are recorded; the human's value is what the contract uses. The machine *proposes*, never silently *commits* a consequential change.
4. **Label it.** "Auto-extracted", "Generated by AI · {model} · {date}", the aurora surface, the spark icon. No pretending the machine output is the user's own.
5. **Fail gracefully.** "Page 4 failed: image too dark — [re-upload page] [skip page] [enter manually]." Never a dead end, never a silent drop.
6. **Make the wait feel like progress.** The processing screen narrates the pipeline (preprocess → OCR → layout → detect → extract → analyze) with a live page preview and a soft "scan" sweep — so 30–120s feels like watching something intelligent work, not staring at a spinner.
7. **Respect cost & scale.** Re-runs are deliberate (a button, optionally on a priority queue, optionally with different settings), results are cached and reused, providers are pluggable so we optimize $/page and $/token without touching the UX.

## 2. The OCR pipeline (what the worker does, in order)

```
S3 file ─▶ ingest (validate, decrypt, page-split, detect "is this a text-PDF?" → skip OCR if so)
        ─▶ per page: PREPROCESS — auto-rotate (deskew), perspective-correct, denoise, binarize/enhance
                     contrast, auto-crop to the document edges, upscale if low-DPI
        ─▶ per page: OCR — language detection per region (Arabic / English / mixed / others), run the
                     OCR engine(s), get text + word-level bounding boxes + per-token confidence
        ─▶ per page: LAYOUT ANALYSIS — segment into paragraphs, headings, lists, headers/footers,
                     columns, and TABLES (cell-level structure); reading-order resolution (critical
                     for Arabic/RTL and multi-column)
        ─▶ per page: DETECTION — signature regions, stamps/seals, handwriting, logos, checkboxes
        ─▶ document: ASSEMBLE — stitch pages into a structured document (text + structure + boxes +
                     confidence), normalize, store as ocr_result (JSONB) linked to document & pages
        ─▶ document: AI PASS (Module 11) — classify type · extract metadata (parties, dates, value,
                     term, renewal, governing law, …) each with a source span + confidence ·
                     detect clauses (map to library) · risk analysis · missing-clause check ·
                     obligations & key dates · summary (EN + AR) · smart tags · per-field confidence
        ─▶ persist ai_extraction (JSONB), emit OCRCompleted + AIAnalysisCompleted events, notify user,
           drop a "Review ready" item in the ProgressTray
        ─▶ on low overall confidence (or user request): offer a re-run (different engine/quality/lang)
```

**Engine strategy (pluggable behind an `OCRProvider` interface):** start with a strong open option (PaddleOCR or Tesseract 5 with Arabic + English trained data, plus a layout/table model like `table-transformer`, plus a doc-preprocessing lib) for cost control and data residency; allow per-tenant/per-job fallback or upgrade to a managed API (AWS Textract, Azure Document Intelligence, Google Document AI) for tricky scans; the AI pass uses an `LLMProvider` interface (Anthropic / OpenAI / a local model) — chosen per tenant/plan, with caching on (document hash + prompt version) so re-opening a review doesn't re-bill. Arabic OCR quality is a known weak spot industry-wide → we invest here (good preprocessing matters more than the engine; reading-order correction; a feedback loop where human corrections build a fine-tuning set).

## 3. The three OCR screens (recap of Modules 8–10, focused on the *feel*)

### 3.1 Upload (Module 8) — "make it as easy as the Dropbox toast looked"
The aurora drop zone with a reassuring capability line ("✓ Arabic + English ✓ tables ✓ signatures & stamps"), drag/browse/**camera**/cloud-picker, a per-file queue exactly like the reference's "Uploading 3 items 78%" toast (name, pages, progress, ✓/⚠/✗ badges, retry), batch options (language hint, preprocessing toggles, post-OCR behavior, default metadata), and then it hands off to the `ProgressTray`. **Mobile camera is the hero**: a guided multi-page capture with live edge detection, per-page re-take, auto-crop, "looks blurry — retake?".

### 3.2 Processing (Module 9) — "make the wait feel intelligent"
A live page preview with a soft **aurora "scan" sweep**, bounding boxes fading in as text is found, a stage checklist ticking through the pipeline ("✓ Preprocess · ⟳ OCR (Arabic+English) · ⟳ Layout & tables · ○ Detect signatures · ○ AI extraction · ○ Risk & summary"), an overall progress bar + ETA, per-file rows (a 1-pager finishes and shows "review →" while a 50-pager is still going), a "run in background" that minimizes to the tray, and graceful per-page failure handling. Implemented via a WebSocket/SSE progress stream from the Celery job (falls back to polling); the job is in the `jobs` table so a page refresh resumes the live view.

### 3.3 Review (Module 10) — **the trust moment**, side-by-side
```
┌───────────── ORIGINAL (DocViewer + confidence-coloured boxes) ──┐ ┌── EXTRACTED (aurora) ──┐
│  the rendered page; boxes are teal/amber/red by confidence;     │ │ ⚡ 9 fields · 2 need you │
│  clicking a field on the right makes its box here PULSE; you    │ │ Type   [MSA ▾]   ●96%   │
│  can also click a box → its field on the right highlights       │ │ Title  [MSA — Acme…]●94% │
│  (bidirectional source-linking)                                 │ │ Party  [Acme Corp]●91%  │
│  page nav, zoom, fit, thumbnails, search-in-doc                 │ │ Eff.   [2026-01-01]●72⚠ │
│                                                                 │ │ End    [________]●41⚠⚠  │ ← red
│                                                                 │ │ Value  [$120k ▾USD]●88  │
│                                                                 │ │ Renewal[Auto ▾] ●77⚠    │
│                                                                 │ │ Gov.law[Oman]   ●83     │
│                                                                 │ │ ─ Clauses(12)▾ Sigs(2)▾ │
│                                                                 │ │   Stamps(1)▾ Tables(1)▾ │
│                                                                 │ │ Languages: ar + en      │
└─────────────────────────────────────────────────────────────────┘ └─────────────────────────┘
 [Re-run OCR ▾]  [Verify all (2) ▸]            [Discard]   [Create contract from this ▸]
```
- **Confidence colour coding** on both the boxes and the chips (teal ≥90 / amber 60–89 / red <60 / gray "not found").
- **"Verify all"** = a focused sweep that walks *only* the amber/red fields one at a time: it highlights the field's source box, shows the candidate value(s), and offers Accept / Edit / Skip / "can't find it in the doc" — so the human spends 30 seconds on the 2 uncertain fields, not 5 minutes re-reading everything.
- **Detected clauses / signatures / stamps / tables** are collapsible lists; each item links to its location; the "table" item opens a mini "map this table's columns to fields" tool when relevant.
- **Re-run OCR** (whole doc or a single bad page; optionally force a language; optionally higher-quality engine; optionally on a priority queue) — for that one smudged page.
- **"Create contract from this"** carries the *verified* values into the creation wizard at the Review step, attaches the source files, links the OCR job, sets status `draft`. (Or, if the upload was in "just extract, don't create" mode, you just get the structured data + a downloadable export.)
- **Batch:** a file strip at the top to move between files in the job; a "verify all & create all" that runs each file's sweep in sequence — turning a 50-document import into a guided 20-minute pass instead of a day.
- **Feedback loop:** when a human overrides a value the model was confident about, that (document region → corrected value) pair can (with tenant consent) feed a labeled dataset for fine-tuning — the product gets better the more it's used, and we *say so*.

## 4. The AI features (mapped to where they surface)

| AI feature (from the brief) | Where it lives | How it's presented |
|---|---|---|
| Contract summarization | Contract detail Overview card + AI Insights + AI Assistant | EN + AR summary, confidence, "shorter/longer/in Arabic", source-linked |
| Metadata extraction | OCR review + AI Insights + the creation wizard pre-fill | per-field value + confidence chip + source span; human-overridable |
| Contract classification | OCR review + AI Insights | "Type: MSA ●96% · Family: Services" + "this doesn't look like a contract" guard |
| Clause detection | AI Insights "Detected clauses" + the editor (highlights clauses) | list of detected clause types, each → its location + "compare to library version" |
| Risk analysis | AI Insights "Risk analysis" + dashboard "Open risks" KPI + AI Recommendations | flagged clauses with severity + rationale + suggested fix + actions (insert standard / request change / accept risk + note); overall risk level |
| Missing-clause suggestions | AI Insights "Missing/recommended" + the editor ("/check for missing clauses") | "no Limitation-of-Liability carve-outs (standard for MSA) — [insert from library]" |
| Smart tagging | AI Insights + auto-applied (with "review") on contract creation | suggested tags chips → accept/edit |
| AI recommendations | Dashboard card + per-contract | "3 auto-renew opt-outs in 30d", "risk spike", "12 obligations due", "missing standard clauses", "duplicate counterparty"; each actionable |
| AI confidence scoring | everywhere a machine output appears | the confidence chip / band; "low confidence overall" banners |
| (also) clause drafting / simplification / translation / "make this more favorable" | the editor's AI commands + the AI Assistant | inline in the editor; "AI draft — review" stamp on anything legally consequential |
| (also) semantic search | `/search` + AI Assistant | NL→filters (always shown & editable) + embedding similarity; results show *why* they matched |
| (also) Q&A | AI Assistant (drawer + full page) | scoped to a contract / folder / "all my contracts"; cites sources; never acts silently |

**Governance & guardrails (because this is contracts):** every AI output is labeled, confidence-scored, source-linked, human-overridable; consequential drafts carry "must be reviewed by counsel"; the AI never auto-approves, auto-signs, or auto-edits a contract; tenant-level controls for "is the AI feature on at all", "are prompts used to improve models" (default off for enterprise), and which model/provider; prompt templates are versioned and reviewed (a "prompt library" in Platform Admin); outputs are monitored (thumbs up/down + "report", aggregate quality dashboards); the AI sees only what the requesting user can see, never another tenant; PII passed to external LLM providers is minimized and covered by DPAs; everything the AI does is in the audit log.

## 5. Performance & scale notes

- OCR and AI run on **their own Celery queues** (`ocr`, `ai`), with workers autoscaled on queue **age**; they can run on GPU node pools (for local models) or call managed APIs; either way the rest of the app is unaffected.
- **Caching:** OCR result keyed by (file hash + preprocessing settings + engine version); AI result keyed by (document content hash + prompt version + model) — re-opening a review or re-viewing insights is free; an explicit "re-run" is the only thing that re-bills.
- **Streaming:** the processing screen and the AI Assistant stream tokens/progress (WebSocket/SSE) for responsiveness; long jobs report incremental progress to the `jobs` table so the `ProgressTray` and any UI can show it.
- **Batch:** a 200-file import is just 200 queued OCR jobs (chunked uploads); the tray aggregates; the user can navigate away; per-file "review now" links appear as each completes; a "verify all & create all" pass handles the human side in one sitting.
- **Cost levers:** provider choice per tenant/plan; "fast/cheap vs thorough/expensive" extraction modes; caching; only re-running on demand; gating advanced AI behind plan tiers; metering AI requests/tokens (shown in billing).
- **Quality levers:** preprocessing (the highest-leverage thing for Arabic), reading-order correction, the human-correction feedback loop, per-language confidence calibration, and a "this scan is poor — re-upload a clearer copy" nudge before the human wastes time.
